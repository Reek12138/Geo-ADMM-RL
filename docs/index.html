问题背景：为什么“让飞机不撞车”比打游戏难得多？

先忘掉复杂的公式，用 30 秒搞懂真实空管防撞到底在解决什么痛点。

✈️ 物理红线极严苛

两架飞机只要同时满足水平距离 < 5 km 且 垂直高度差 < 300 ft（91.44 m），就算严重碰撞（Loss of Separation）。而且飞机偏离航路中心线超过 20 km 就算越界。

🐢 延迟与惯性很大

飞机每 6 秒才接收一次控制指令，但底层物理每 0.05 秒积分一次（B737 气动模型）。你让它爬升 300 ft，它需要几十秒慢慢爬上去；你让它转弯，它会自动关掉航路跟踪 LNAV，如果不掰回来就会一路飞出界！

🕸️ 多机“二次冲突”陷阱

天上不是只有两架飞机。如果飞机 A 为了躲开 B 盲目下降高度，很可能一头扎进原本安全飞在下层的飞机 C——这就是空管里最头疼的链式二次冲突。

💡 一句话讲懂本项目的核心设计哲学：
传统离线数学优化（如 MILP/NLP）算得准但飞机一多算不动、怕突发变化；传统端到端 RL（如 SARL）反应快但小网络看不远、容易违规。
Geo-ADMM-RL 把两者合体：用 3 层图 Transformer 当“大脑”（看穿未来 2 分钟的链式冲突、学会省油的稀疏指令），再把分布式解析优化 ADMM 做成“条件反射安全层”（哪怕大脑偶尔犯糊涂，也用数学公式在 6 毫秒内把动作掰回安全区）。

神经网络怎么“看”天空？—— 时空冲突图（节点 24 维 + 边 18 维）

如果直接把每架飞机的经纬度拼接成长向量喂给 MLP，飞机一增减网络就废了，换个空域就过拟合。我们把空域建模成一张物理图 G(t) = (V, E)。

🟦 节点特征：每架飞机自己的 24 维“体检表”

全部采用相对局部坐标系（保证旋转、平移不变性，换个地图照样认识）：

  • 运动状态：速度偏差、高度与目标航路高度差、垂直速度；
  • 航路导航：距离终点剩余航程、偏离航路横向距离 xtk、目标航向夹角 sin/cos、LNAV 开关状态；
  • 物理边界：当前速度离上下限 [200, 300 kts] 还剩多少余量、上下邻近高度层是否被占用；
  • 历史与图位置：上一步动作模式、自己在冲突图里的邻居数量（节点度）。

🔗 边特征：两架飞机之间的 18 维“物理关系卡”

只对 20 km 内且未来存在既有或潜在冲突风险的飞机连边（剪掉 80%+ 无关边）：

  • 3D 相对几何：相对位置、相对速度矢量、当前水平/垂直距离；
  • 连续时间解析预测（源自 Geometry-UAV-CDR）：不靠时间步离散采样，直接用几何公式算出未来 120s 内的精确最小间距 d_min 以及进入/退出冲突时间 [t_enter, t_exit]；
  • 既有 vs 潜在冲突标记：不仅标出“照现在飞会撞的”，还标出“现在不撞但一调速/降高就会撞上的”邻居；
  • RSTD 速度禁行区：算出哪一段速度区间绝对不能选，直接告诉网络！
🧩 图论剪枝的妙处（连通分量 + 图着色）： 在每个 6 秒控制步，先按冲突边把全空域拆成几个互不相连的独立子图（连通分量）——没有连边的孤立飞机直接 Hold 省油巡航；子图内部用图着色给相邻冲突飞机涂不同颜色，同色飞机互不冲突可 100% 并行协商，避免两架飞机同步乱让陷入震荡！

📐 细节深挖：不用时间步采样，怎么“一步解析”算出冲突与潜在冲突？

传统方法把未来 120 秒切成 120 份逐秒查距离，既慢又容易在两秒之间漏检碰撞。本项目借鉴了 Geometry-UAV-CDR 的连续时间解析思想：假设两架飞机在预测窗口 [0, H]（H = 120s）内做相对匀速运动，设初始相对位置为 Δp = p_j - p_i，相对速度为 Δv = v_j - v_i：

t_cpa = clamp( -(Δp · Δv) / (||Δv||² + ε), 0, H ) // 最近会遇时刻（解析求导置零！）
d_min = || Δp + Δv · t_cpa || // 窗口内连续时间精确最小水平距离
margin = d_min - r_safe (r_safe = 5.0 km) // 安全裕度：< 0 为既有冲突，接近 0 为潜在冲突
既有冲突边

照当前速度飞下去 d_min < 5km 且垂直高差 < 300ft——必须立刻消解。

潜在冲突边

当前时间错开了，但空间航段最小距离 < 5km（或位于 ±300ft 相邻高度层）——防二次冲突的关键！

RSTD 速度禁行区

直接解二次不等式 d_min(v_i) < r_safe，算出绝对不能选的速度区间 [v_lo, v_hi] 喂进边特征。

🔍 逐层前向数据流拆解（本科生也能跟着算一遍！）

假设一次并行处理 B 个空域、每个空域最多 N 架飞机，下面完整追踪一条观测穿过 models/graphformer.py 的每一步计算：

// Step 1: 线性投影到隐空间 width = 256
h^(0) = Linear(24 → 256)(node_features) // [B, N, 256]
e^(0) = Linear(18 → 256)(edge_features) * adj // [B, N, N, 256]，无冲突边强制清零

// Step 2: 重复 3 层 Edge-Biased GraphLayer（每层 8 头，每头 d_k = 32）
Q, K, V = split( Linear(LayerNorm(h)) ) // 各 [B, N, 8, 32]
E_K, E_V, bias = MLP(e) // 边特征变成注意力偏置与键值修正
Attn_ij = Softmax_j( (Q_i · (K_j + E_K_ij)) / √32 + bias_ij ) // 只在冲突邻居 + 自身上聚合
h' = h + OutputLinear( Σ_j Attn_ij · (V_j + E_V_ij) ) // 节点吸收邻居风险信息
h_next = h' + SwiGLU( LayerNorm(h') ) // 门控前馈网络 (4x 隐层)
e_next = LayerNorm( e + MLP( e + Send(h_next_i) + Recv(h_next_j) ) ) // 边嵌入同步进化！

// Step 3A: 稀疏控制头 (SC-MoE)
mode = GumbelSoftmax( Router(h^(3)), hard=True ) // 4 选 1: [Hold, Speed, Alt, Hdg]
hdg_out = raw_hdg + ( where(|raw_hdg| ≥ 0.05, raw_hdg, 0) - raw_hdg ).detach() // STE 0.05 死区保 LNAV

// Step 3B: ADMM 神经热启动头（强制数学双边对称）
dual_ij = 0.5 * ( d_ij + flip(d_ji) ) // 保证飞机 i 和 j 看到的对偶初值互为镜像
rho_ij = Softplus( 0.5 * (p_ij + p_ji) ) + 0.1 // 正惩罚系数，bias 初始化 7.9 防起步发散
β_ij = s_i / (s_i + s_j), s_i = Softplus(Linear(h_i)) + 1e-3 // 严格满足 β_ij + β_ji = 1

分布式 MPC-ADMM 安全层：不用“总调度员”怎么集体避撞？

本科生最容易问：这么多飞机没有中央总控，怎么避免互相撞上或者陷入僵局？答案是 ADMM 三步分账法 + 滚动预测 MPC。

1

第一步：各自算小账（Primal 更新 —— 本地极速闭式）

每架飞机先不管复杂的避撞方程，只平衡“我最想飞的省油动作 u_raw”和“上一轮跟邻居商量好的参考值 z_ij”。因为不含非线性碰撞约束，直接一行公式算出自己的新提案。

2

第二步：冲突邻居一对一碰头（Consensus 解析投影 —— 优先调速、再分层）

只向冲突图里有连边的邻居发一条极短消息，每条边独立解一个超小的 2 机连续时间解析投影（复用 6 种几何情况公式）：先看能不能仅靠微调速度避开（不关 LNAV、最省油）；如果像对头/六航路中心那样纯调速无解，则自动升级到 Tier 2 三机联合高度层搜索（按有效空域分块后，512 个空域并行求解仅需 6.82 ms！）和逐机局部航向保护。

3

第三步：记“矛盾账本”（Dual 对偶更新 —— 自动化解多机死锁）

如果飞机 A 同时夹在 B 和 C 中间，B 让 A 加速、C 让 A 减速，A 就把分歧累加到边账本 λ_ij 里。下一轮分歧越大的边权重越高，自动把压力传导给周围空旷的邻居让它多让一步！由于 GraphFormer 提前给出了聪明的神经热启动 (dual, rho, willingness)，原本要聊 10～20 轮的 ADMM 现在只需 K = 2 轮就能快速收敛。

进阶：低频通信 / 丢包怎么办？—— 空窗步 120s MPC 预测兜底

真实天空通信可能延迟（1～2 步）、丢包（20%），或者每 18 秒才通一次信。我们加上了 --admm-gap-policy mpc：没收到新消息的空窗步里，飞机直接拿上一轮协商好的轨迹，用局部 120 秒滚动预测筛选安全动作，在 18s 低频通信实测中把到达/碰撞从 7/4 直接拉到了 11/0（零碰撞）！

🧮 本科生秒懂的 ADMM 三步迭代公式 & 多机死锁调和例子

// ① 本地 Primal 更新（无碰撞约束，一行闭式加权平均！）
u_i^(k) = Clip( [ W_i · u_i^(0) + Σ_{j∈N_i} ρ_ij · (z_ij^(k-1) - λ_ij^(k-1)) ] / [ W_i + Σ_{j∈N_i} ρ_ij ] )

// ② 冲突边 Consensus 解析投影（仅相邻冲突机通信，2 机微秒级投影）
(z_ij^(k), z_ji^(k)) = Project_{d_min(z_i, z_j) ≥ r_s} ( u_i^(k) + λ_ij^(k-1), u_j^(k) + λ_ji^(k-1); β_ij )

// ③ 本地 Dual 矛盾账本更新（分歧不断累加，逼迫空旷邻居主动让步）
λ_ij^(k) = λ_ij^(k-1) + u_i^(k) - z_ij^(k)

举个生活算例：假设六航路中心 飞机 A 同时和 B、C 有冲突：B 希望 A 加速 +4 kts，C 希望 A 减速 -4 kts。第 1 轮里 A 折中不动（0 kts），于是边 (A,B) 的账本记下分歧 -4、边 (A,C) 记下 +4；第 2 轮里如果 B 周围没其他飞机（s_B 让步意愿大），账本压力就会直接把 B 推向“自己大幅减速让路”，而 C 微微加速——完全不需要中央总控，三机僵局在 2 轮局部对话内自然解开！

坑 1：为什么 1 步 TD 看不见 2 分钟后的撞机？

现象：飞机提前 1 分钟微微减速就能避免六航路相撞，但旧版 Critic（1 步 TD）给 4 个正确提前避碰方案只认出 1/4。
解法：升级为 24 步（144 秒）多步回报（--return-window 24 --multi-step-return），把 2 分钟后交叉点的撞机惩罚直接折现传回当前步，Critic 识别率立刻跃升至 3/4～4/4！

坑 2：为什么 Actor 越训负偏航越差？（46.7% 梯度反号！）

现象：Critic 一直是在“安全层投影后的动作 a_exec”上训练的，但 Actor 却把“未投影的 a_raw”直接喂给 Critic 求梯度，导致 a_raw 处属于分布外（OOD），负偏航竟有 7/15 批次梯度指反了方向！
解法：引入 --projected-actor-ste（前向用 a_exec 给 Critic 精准打分，反向梯度通过直通估计器传回 Actor），负偏航反号瞬间从 7/15 归零到 0/15！

坑 3：为什么 +15° 偏航满分，-15° 总是掉链子？

现象：明明左右镜像对称的任务，+15° 经常 36/36，-15° 却老掉到 31/36，而且旧保护逻辑一刀切清零航向导致偏航全越界。
解法：① 改成逐机局部航向保护（只拦危险转向，放行孤立飞机回航）；② 加入 --mirror-replay 左右镜像数据增强，把每一条样本水平翻转成对入库，直接抹平左右不对称。

坑 4（硬核科研彩蛋）：2 毫米的“假安全”擦边碰撞！

最新定位：垂直撞机红线是 300 ft = 91.44 m。审计 3 对六航路碰撞发现：安全层用匀速近似算出高差 94.03 / 93.18 / 92.96 m（以为安全放行了），但原生 BlueSky 带 300 fpm 垂向加速度惯性跑出来的真实高差是 91.187 / 91.438 / 91.401 m——就差 2 毫米到 25 厘米被判碰撞！用精确 B737 垂向积分复算误差仅 4.1 微米，替换后可精准清零这一整类碰撞。

⚙️ 一次 TD3 梯度更新里究竟发生了什么？（5 步完整拆解）

1. 奖励函数怎么设计？（让飞机“安全、省油、不乱动”）

  • 终局奖惩：安全抵达目的地 +200，发生碰撞 -50，横向偏离 > 20 km 越界重罚；
  • 过程引导：沿航路前进奖励、横向偏移 xtk 惩罚、航向对准奖励；
  • 动作成本分级权重：调速 / 升降 / 航向按 1 : 2 : 4 线性加权——明确告诉 RL“能 Hold 就不动，能微调速度就别升降，尽量别动航向关 LNAV！”；
  • 安全层介入归因：安全层修正动作的惩罚直接记在导致介入的 raw 动作头上。

2. 每一步梯度更新的 5 个标准动作（train/td3.py）

  1. 从 PPU 显存常驻 Replay Buffer 抽一批 24 步（144s）多步回报转移（含左右镜像样本）；
  2. 用 Target Actor 算下一步动作，经同一安全投影得到 a_next_exec，算 y_i = R_24 + γ^24 · min(Q1', Q2')；
  3. 用 Smooth L1 Loss 同步更新 Twin Critic (Q1, Q2)，梯度裁剪 5.0；
  4. 每 2 步延迟更新 Actor：前向用 a_ste = a_raw + (a_exec - a_raw).detach() 让 Q1 精准打分，叠加短期线性衰减锚定（前 2k 步归零），反向更新 Actor（最新还支持 --freeze-actor-encoder 防共享编码器漂移破坏 ADMM 头）；
  5. 对 Target Actor / Target Critic 做 τ = 0.005 指数滑动平均软更新。
